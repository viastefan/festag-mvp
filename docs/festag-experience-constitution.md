# Festag Experience Constitution

**How Festag should feel.**

Not features. Not components. Not layouts.

Cursor rule: `.cursor/rules/festag-experience-constitution.mdc`  
Product law (what we build): `docs/festag-product-constitution.md`

────────────────────────────────────────

## Design philosophy

Users should never feel they are using software.

Users should feel they entered an intelligent operating system.

Everything should feel: calm · confident · professional · invisible · expensive · timeless.

Never trendy. Never childish. Never noisy. Never over-designed. Never “AI-looking.” Never futuristic for its own sake.

Technology disappears. Work becomes clear.

## The Festag feeling

Imagine combining Apple’s calm, Stripe’s confidence, Linear’s speed, Vercel’s precision, and Notion’s clarity — without copying any of them.

Festag must feel like its own company.

Someone should immediately recognize: “This feels like Festag.”

## Visual language

- Whitespace is a feature.
- Typography is navigation.
- Motion communicates intelligence.
- Contrast creates hierarchy.
- Everything has room to breathe.
- Never fill space because space exists.
- Every pixel must justify itself.

## Design decision rule

Whenever multiple solutions exist, always choose the solution that feels:

simpler · calmer · more obvious · more timeless · more premium · less distracting

Never add visual elements only because they look cool.

## Animation system

Animation communicates **state**. Never decoration.

Every animation must answer:

- What appeared?
- Why did it appear?
- Where did it come from?
- Where did it go?

Animations should feel almost invisible. Nothing should surprise the user. Everything should simply make sense.

### Loading

Never show empty screens. Never flash content. Never suddenly replace large layouts.

Instead: fade → prepare → assemble → reveal.

The interface should feel like it is building itself.

### Workspace initialization

Opening Festag should feel different from opening a normal application.

Example (extremely subtle, **600–1500ms**, never fake long loading):

Opening Workspace… → Understanding Context… → Preparing Intelligence… → Ready.

Only communicate intelligence.

### Module appearance

Cards should never appear all at once.

Preferred sequence: Workspace Header → Tagro Briefing → Projects → Focus → Activity → Secondary modules.

Each section fades naturally — almost impossible to notice consciously.

### Micro interactions

Buttons never jump. Cards never bounce. Hover is soft. Press feels physical. Scrolling feels attached.

Nothing vibrates. Nothing overshoots. Everything feels engineered.

## Navigation

Navigation should disappear mentally. Users should never think “Where is this?”

Consistency is more important than creativity.

## Tagro

Tagro is not the center of attention. Tagro quietly runs the operating system.

Appears only when useful. Never interrupts. Suggests — never forces.

Speaks with confidence. Never excitement. Never emojis. Never hype.

Sounds like an experienced Chief Operating Officer.

## Panels

Panels feel connected — never floating randomly or isolated.

Every panel belongs to the system. Spacing creates relationships — not borders.

## Cards

Cards are not containers. Cards represent information groups.

Every card answers **one** question. Never combine unrelated information.

One purpose. One hierarchy.

## Typography

Typography creates structure — not color.

Large headlines. Comfortable reading width. Clear spacing.

Never tiny labels everywhere. Never visual clutter.

If typography alone cannot create hierarchy, the layout is wrong.

## Colors

Color communicates meaning — not decoration.

Accent colors are rare.

Errors feel calm. Warnings feel informative. Success feels reassuring.

Never loud.

## Empty states

Empty does not mean unfinished.

Empty states teach, guide, inspire.

Never blame users. Never feel broken.

## Responsiveness

Desktop · Tablet · Mobile · Watch.

Every experience feels intentionally designed — never compressed, never stretched.

Every breakpoint deserves individual attention.

## Authentication

The **Developer onboarding** already represents the desired visual language.

Treat it as the authentication design system.

**Expand it. Do not redesign it.**

Login · Register · Invite · Workspace Creation · Reset Password · Forgot Password · Verify Email · Join Project

All authentication pages evolve from this design. Improve details continuously. Never replace the foundation.

## Evolution

Do not freeze the UI. Continuously improve it.

Whenever a screen can become clearer, simpler, more elegant, more premium, more obvious — improve it.

Never be afraid to remove elements.

The product should become **calmer every month** — not bigger.

## Self-review

Before committing any UI change, ask:

1. Is this simpler?
2. Does this remove cognitive load?
3. Would Apple remove something here?
4. Would Linear simplify this?
5. Would Stripe make this calmer?
6. Does this still feel unmistakably like Festag?

If the answer is no — continue refining before shipping.

## Final principle

Festag should not impress through complexity.

Festag should impress through clarity.

The best interface is the one users stop noticing.

Every release should move Festag closer to becoming the world’s most intelligent and calm operating system for projects.
